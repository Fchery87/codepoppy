# AI pull request review market scan

**Checked:** October 14, 2026. **Scope:** Official product documentation for CodeRabbit, Greptile, Qodo, GitHub Copilot code review, and Graphite. These pages describe vendor capabilities, not independently measured review accuracy.

**Decision status:** Historical market evidence. The gaps described against the earlier PRD were resolved in PRD 3.0 and ADRs 0057–0063. The recommendations below preserve the research rationale, not the current implementation contract.

## What products currently offer

| Product | Documented review experience |
|---|---|
| CodeRabbit | Pull request summaries, inline review, codebase context, path-specific instructions, learnings, and fixes. [CodeRabbit pull request reviews](https://docs.coderabbit.ai/overview/pull-request-review.md), [CodeRabbit knowledge base](https://docs.coderabbit.ai/knowledge-base/index.md), [CodeRabbit fix comments](https://docs.coderabbit.ai/finishing-touches/autofix.md) |
| Greptile | Automatic PR comments based on a repository graph, suggested fixes, feedback from reactions and replies, and an agent handoff for fixes. Its documentation also lists self-hosted deployment. [Greptile overview](https://www.greptile.com/docs/introduction) |
| Qodo | Automatic review with configurable inline severity thresholds and repository-level review guidelines. It also supports PR and file exclusions. [Qodo configuration](https://docs.qodo.ai/qodo-documentation/code-review/get-started/configuration-overview/configuration-file), [Qodo exclusions](https://docs.qodo.ai/qodo-documentation/code-review/concepts) |
| GitHub Copilot code review | Manual or automatic reviews, optional reviews on new pushes and drafts, inline suggestions, reaction feedback, and repository and path-specific instructions. [GitHub review workflow](https://docs.github.com/en/copilot/how-tos/copilot-on-github/use-copilot-agents/copilot-code-review), [GitHub custom instructions](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/request-a-code-review/use-code-review) |
| Graphite | Automatic inline bug findings with explanations and suggested fixes, codebase context, custom rules and exclusions, and acceptance analytics. [Graphite AI reviews](https://graphite.com/docs/ai-reviews), [Graphite review comments](https://graphite.com/docs/ai-review-comments) |

The common product promise is an actionable finding where the developer reviews code. This is an inference from the five documented workflows above. A private analysis dashboard alone does not meet that promise.

## Recommended changes to CodePoppy

| Priority | Change | Why it belongs here |
|---|---|---|
| Must have for a usable release | Make publication of a concise summary and high-confidence inline findings the first user-facing milestone. Keep a short shadow qualification period and exact-head publication checks. | The [PRD](../CodePoppy-PRD.md) ends its first release before GitHub output. Every product above delivers findings in the PR. The [product direction review](product-direction-review.md) already identifies this gap. |
| Must have for a usable release | Define the finding contract: failure scenario, changed line, supporting context, consequence, specific next step, and a visible way to dismiss or dispute the finding. Record dispute outcomes for evaluation. | Graphite documents inline comments with a problem, impact, and fix; GitHub documents reactions and replies on review comments. [Graphite review comments](https://graphite.com/docs/ai-review-comments), [GitHub review workflow](https://docs.github.com/en/copilot/how-tos/copilot-on-github/use-copilot-agents/copilot-code-review). The PRD defines severity and verification, but not the developer-facing format or PR feedback handling. |
| Must have for a usable release | Measure time to visible review, coverage, actionable precision by severity, and repeated or stale comments on live PRs. Report the sample size and inspected misses. | Competitors emphasize timely PR feedback; Graphite exposes acceptance and downvote metrics. [Graphite review comments](https://graphite.com/docs/ai-review-comments). CodePoppy's current gate measures some quality, but its per-repository requirement for 15 real actionable findings can block quiet repositories indefinitely. This is a product judgment based on the [PRD gate](../CodePoppy-PRD.md). |
| Must have for a usable release | Provide a guided self-host setup with a doctor check that proves webhook delivery, runner claim, model routing, and one completed shadow review. Measure time to first review on a fresh installation. | [CodeRabbit](https://docs.coderabbit.ai/getting-started/quickstart.md) and [Greptile](https://www.greptile.com/docs/introduction) present a short path from connection to review. CodePoppy asks one person to supply a GitHub App, Workers deployment, Postgres, a private runner repository, and model keys. Its current acceptance says only that deployment can be reproduced. |
| Next after usable release | Add narrow, path-specific review guidance that can express project invariants and intentional exceptions. Read only trusted base-branch guidance. | CodeRabbit, Copilot, Qodo, and Graphite document configurable review guidance. [CodeRabbit path instructions](https://docs.coderabbit.ai/configuration/path-instructions.md), [GitHub custom instructions](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/request-a-code-review/use-code-review), [Qodo configuration](https://docs.qodo.ai/qodo-documentation/code-review/get-started/configuration-overview/configuration-file), [Graphite customization](https://graphite.com/docs/ai-review-customization). The PRD's config controls profile, routes, and excludes, but does not define project-specific review rules. |
| Next after usable release | Evaluate cross-file impact using selected callers, interfaces, and tests when the changed symbol warrants it. Record the added context and its cost. | Greptile and GitHub explicitly describe repository-wide context. [Greptile overview](https://www.greptile.com/docs/introduction), [GitHub overview](https://docs.github.com/en/copilot/concepts/agents/code-review). The PRD currently limits automatic context mainly to the hunk, enclosing symbol, direct imports, and matching tests. Broad indexing is an implementation choice, not a prerequisite. |
| Later, after finding quality is proven | Publish bounded, applicable GitHub suggestions and support a deliberate fix workflow. | CodeRabbit, Greptile, Qodo, Copilot, and Graphite all document suggested fixes or an agent handoff. [CodeRabbit fix comments](https://docs.coderabbit.ai/finishing-touches/autofix.md), [Greptile overview](https://www.greptile.com/docs/introduction), [Qodo suggestions](https://docs.qodo.ai/qodo-documentation/qodo-merge/tools/tools-list/improve), [GitHub review workflow](https://docs.github.com/en/copilot/how-tos/copilot-on-github/use-copilot-agents/copilot-code-review), [Graphite review comments](https://graphite.com/docs/ai-review-comments). CodePoppy already specifies a bounded suggestion shape, but defers publication. |

## Do not chase yet

Multi-user administration, GitLab and Bitbucket, ticket integrations, chat, merge approvals, and automatic code edits expand the product beyond a personal self-hosted GitHub reviewer. Competitors offer some of these, but the first useful CodePoppy release depends more on accurate findings, safe publication, and low setup friction. Keep the PRD's self-hosting acceptance criterion and test it with a fresh installation.
